# Time / Timezone / Date

บั๊กเวลาโผล่ช้าและ reproduce ยาก — กันตั้งแต่เขียน:

## เก็บ / คำนวณ
- **เก็บเป็น UTC เสมอ** (timestamptz / epoch) — timezone เป็นเรื่องของ*การแสดงผล*
  ไม่ใช่การเก็บ; ห้ามเก็บ local time โดยไม่มี offset
- **ห้ามเทียบ/parse วันที่จาก string** — ใช้ date type/lib เสมอ; `"2026-07-08" > "2026-6-9"`
  คือบั๊กที่รอวันเกิด
- **ห้ามเอา now (มีเวลา) ลบ date-only แล้วอ่านจำนวนวัน** — เศษชั่วโมงโดน truncate
  เหลือ 0 วัน; นับวันให้ anchor ทั้งคู่เป็น calendar date ใน business timezone ก่อน
- **โค้ดที่ถูกเพราะ server ตั้ง TZ ไว้พอดี = ระเบิดรอเวลา** — ใช้ zoned math ชัดเจน
  หรือ assert TZ ตอน boot; ห้ามพึ่ง `TZ` env โดยไม่รู้ตัว
- **date arithmetic ต้อง DST-safe** — "อีก 30 วัน" กับ "อีก 720 ชั่วโมง" ไม่เท่ากันเสมอ;
  ข้ามเดือน/ปีอธิกสุรทินให้ lib จัดการ ไม่บวกเลขเอง
- การเทียบเชิงธุรกิจ (เช่น สิทธิ์ก่อน/หลังลาออก, cutoff รอบบัญชี) ต้องนิยามชัดว่า
  ใช้ timezone ไหนตัดวัน และเขียน test คร่อมเส้นตัด (เที่ยงคืน, สิ้นเดือน)

## แสดงผล / กำหนดการ
- แสดงผลตาม timezone ของ user หรือของธุรกิจ และบันทึก decision ใน operational context
  ที่ตรวจพบใน repo (เช่น Asia/Bangkok) — อย่าปล่อยให้บางจอ UTC บางจอ local
- **cron/schedule ระบุ timezone ชัดทุกตัว** — "14:00" ไม่พอ ต้อง "14:00 Asia/Bangkok"
- range query ("ยอดเดือนนี้") แปลงขอบเขตจาก business timezone → UTC ก่อน query
  ไม่ใช่ตัดที่ UTC ตรง ๆ

ก่อนปิดงานที่แตะเวลา: ลองเคสข้ามเที่ยงคืน + ข้ามเดือน + user คนละ timezone อย่างน้อยหนึ่งรอบ
